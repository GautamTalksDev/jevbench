# Threat model

This repository is a static research project. Nothing here logs in a user or stores a database. The table is what Prompt T actually hardened.

| Asset | Threat | Mitigation | Residual risk |
|---|---|---|---|
| GitHub Actions token and any future secret | A pull request workflow runs untrusted code with the base repository's credentials, as in the 2025 `pull_request_target` worm | Workflows are `contents: read` by default. Extra permissions are per job. No `pull_request_target`. No `workflow_run` on untrusted input. Actions are pinned to commit SHAs. CI does not receive the Jev API key. zizmor runs on the workflows. | A maintainer can still approve a malicious workflow change. Fork pull requests can run CI until GitHub's "require approval for outside collaborators" setting is turned on by hand. |
| Preregistration and results | A force-push, a sloppy pull request, or a "fix" after unblinding rewrites the locked analysis | `PREREGISTRATION.md` is hash-pinned. The integrity job fails if that digest or the locked dataset hashes change. CODEOWNERS names the maintainer. Contribution rules refuse ordinary edits to frozen files. | GitHub branch rulesets are not in the repository. They have to be clicked on after the repo is public. A maintainer bypass can still rewrite history. |
| Arena page | `?run=` fetches an attacker URL, or certificate JSON is inserted as HTML | `?run=` accepts only `data/<name>.json` on this origin. JSON fields are written with `textContent`. A strict Content-Security-Policy meta tag blocks inline scripts and remote origins. Certificates must use schema `jevbench.certificate.v1` and stay under 20 MB. | The page is only as safe as the host. A broken deploy that strips the CSP meta tag would reopen the issue. Phishing can still copy the visual design on another site. |
| Jev API key | The key lands in a log, a run file, or a workflow | `.env.example` has an empty placeholder. The loader's error does not print the value. Run writers refuse a file that contains the key. Workflows are tested so they do not name other secrets. | The key in a developer environment is outside the repo. Rotate it after EXP-1. GitHub secret scanning has to be enabled in the repository settings. |
| Dependencies | A compromised action or Python package | Dependabot is weekly for actions and pip. pip-audit runs on the installed set. OpenSSF Scorecard is scheduled. | Scorecard and Dependabot alerts only help if someone reads them. pip-audit cannot see a package that is installed later on a laptop. |

What this repository cannot do: block a person, rate-limit comments, or stop a force-push. Those are GitHub settings (interaction limits, branch rulesets, and required approval before fork workflows run). Do not add an issue-triage bot that holds a write token and can be triggered by strangers.
